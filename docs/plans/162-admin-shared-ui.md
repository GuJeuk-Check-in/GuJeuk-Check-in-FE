# #162 관리자 공통 UI·테마 정리

## 확정 범위
- 구즉 관리자와 법동 관리자만 변경한다. 구즉 체크인 앱은 제외한다.
- 구즉의 화면, API 호출, 라우팅, 검증 문구와 비밀번호 변경 완료 흐름을 유지한다.
- 법동은 구즉의 폰트·규격을 공유하며 지정 Figma 프레임의 색상만 적용한다.
- 법동 본문 퍼블리싱과 실제 인증 API 연동은 후속 작업이다. 연결되지 않은 API의 성공을 가장하지 않는다.

## 경계 및 실행 순서
1. 변경 전 구즉 인증 화면의 화면·입력 검증을 브라우저로 기록한다.
2. `@center/tokens`에 색상·타이포그래피·기본 규격과 기관별 테마를 둔다.
3. `@center/ui`에 인증 UI/검증, 버튼, 필드, 선택창, 검색창, 모달, 카드·사이드바 틀을 추출한다.
4. 앱은 API·스토어·라우팅·필드 구성·메뉴·권한을 소유한다. 기존 구즉 import 경로는 재수출로 보존한다.
5. 두 관리자 앱을 공통 인증 UI로 전환한다. 법동은 연결 준비 전 안내를 유지한다.
6. 인증 회귀 검증, 공통 UI 사용 검증, 관리자 두 앱 및 공통 패키지 lint/typecheck/build/architecture를 실행한다.

## 회귀 기준
- 비어 있는 기관명/비밀번호, 공백 입력, 비밀번호 확인 불일치, 오류 후 재입력, Enter와 비밀번호 표시 전환.
- 구즉 로그인 성공·서버 오류와 비밀번호 변경 성공/실패, 완료 버튼 후 로그아웃·이동.
- 구즉 로그인/비밀번호 화면의 데스크톱·모바일 크기·폰트·색상 비교.
- 목록 카드 이동/삭제 분리, 검색 초기화, 선택창과 읽기 전용/수정 필드, 사이드바 메뉴 동작 유지.
- 기관별 테마 예외가 다른 기관으로 번지지 않으며, 공통 패키지가 앱 내부 경로를 참조하지 않는다.

## 작성 규칙
로직·컴포넌트를 파일 위쪽에, 스타일·애니메이션을 아래쪽에 둔다. 외부 의존성을 추가하지 않는다.

## 구현 및 검증 결과
- `@center/tokens`와 `@center/ui`를 추가하고 구즉의 기존 import 경로를 얇은 어댑터·재수출로 유지했다.
- 두 관리자 앱에 동일한 폰트·규격과 기관별 색상 테마를 적용했다. 카드 정보·필드 순서·API·메뉴·라우팅은 앱에 남겼다.
- `yarn check:gujeuk-admin`, `yarn check:beopdong-admin`, `yarn check:admin-shared` 통과.
- 삭제 전 인증 DOM·CSS 18개 비교 통과.
- 삭제 전 본문 DOM·CSS 34개 비교와 테마·규격 격리 3개 통과.
- 공통 검증 규칙 17개와 테마 계약 2개 테스트 통과.
- 브라우저에서 필수 입력·Enter·비밀번호 표시·불일치 오류, 검색 초기화·기타 지역·선택창·카드 이동/삭제 분리·목적 수정/취소·사이드바를 확인했다.
- 비밀번호 완료·오류 모달과 완료 후 로그아웃 콜백·로그인 경로 이동은 외부 API 없는 합성 응답으로 확인했다.
- 두 관리자 인증 화면을 일반 창과 390×844 CSS px iframe에서 확인했다. 변경 전 모바일 픽셀 캡처와의 비교는 수행하지 않았으며, 반응형 CSS 보존은 당시 고정 fixture 비교로 검증했다.

검증 완료 후 요청에 따라 이번 작업의 테스트 코드, QA 화면, mock·fixture 데이터와 검증 산출물을 삭제했다. CI에는 공통 패키지 타입·린트 검사만 유지한다.

기존 구즉 아키텍처 경고 6건과 목적 카드의 `isDeleting` DOM 속성 경고는 기존 상태를 유지했다. 중간 폭 인증 레이아웃의 내부 스크롤도 기존 CSS대로 유지한다. 실제 인증 서버 통합 검증과 법동 본문 퍼블리싱은 이번 범위에 포함하지 않는다.
