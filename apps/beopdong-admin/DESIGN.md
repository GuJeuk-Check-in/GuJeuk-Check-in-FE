# 법동 관리자 화면 기준

## 1. 범위와 기준
- 관리자 레이아웃과 왼쪽 사이드바를 구현한다. 상단 헤더는 추가하지 않는다.
- Figma `10049:5412`의 로고, 메뉴 순서, 하단 내보내기 버튼을 기준으로 한다.
- 폰트와 기본 규격은 기존 관리자 공통 UI를 따르고 색상만 법동 테마를 사용한다.
- 방명록 목록·상세 조회를 구현하며, 실제 API와 엑셀 생성은 후속 단계다.

## 2. 색상
- `@center/tokens`의 `orangeTheme`를 사용한다.
- 배경·강조: `colors.primary`, 활성 메뉴: `colors.primaryDark`.
- 사이드바·안내 영역: `colors.white`, 기본 글자: `colors.text`.
- 보조 글자: `colors.secondaryText`, 포커스: `colors.primaryDark`.

## 3. 타이포그래피
- 글꼴은 공통 `typography.bodyFamily`를 상속한다.
- 메뉴는 구즉과 같은 공통 `MenuButton`의 1.5rem·400을 사용하며 활성 상태는 법동 색상으로 구분한다.
- 내보내기는 공통 `ExportButton`의 1.1rem·600을 따른다.
- 페이지 제목은 2rem·700, 안내는 1.25rem으로 구성한다.

## 4. 배치와 스크롤
- 공통 `AdminShell`과 `Sidebar`를 조합하는 `fixed-sidenav-shell` 구조다.
- 사이드바 폭은 공통 `components.sidebarWidth`를 유지한다.
- 본문 세로 스크롤은 문서, 사이드바의 긴 메뉴는 사이드바 자체가 담당한다.
- 관리자 레이아웃이 표시되는 동안 문서 배경도 `colors.primary`를 사용해 절대 배치된 달력이 본문 아래로 펼쳐져도 배경이 끊기지 않게 한다. 인증 화면으로 이동하면 이 문서 배경 적용을 해제한다.
- 로고·메뉴·내보내기 순서이며, 내보내기는 여유 공간 아래쪽에 배치한다.
- 데스크톱 메뉴의 기본 패딩·행 높이·글꼴은 공통 버튼을 그대로 사용하고 메뉴 간격은 구즉의 2rem이다. 로고는 공통 15rem 너비·하단 3rem 간격을 사용한다.
- 48rem 이하에서는 사이드바를 문서 흐름으로 전환하고 메뉴를 두 열로 배치한다.
- 작은 화면에서 본문을 사이드바 폭만큼 밀거나 가로 스크롤을 만들지 않는다.
- StyleGallery 원격 카탈로그는 DNS 연결 실패로 조회하지 못했다. 기존 공통 셸을 기준으로 한다.

## 5. 컴포넌트와 상태
- `AdminShell`: 사이드바와 `Outlet` 본문을 배치한다. 기관별 CSS 확장을 허용한다.
- `Sidebar`: 로고 링크, 실제 경로를 가진 메뉴 링크, 내보내기 버튼을 배치한다.
- 메뉴: 기본·hover·현재 경로·키보드 focus 상태. 상세 경로도 상위 메뉴를 활성화한다.
- `ExportButton`: 공통 버튼을 재사용하고 Figma 원본 아이콘을 전달한다.
- 내보내기는 연결 전 disabled 상태이며 성공이나 다운로드를 가장하지 않는다.
- 후속 본문 페이지는 현재 페이지 제목과 준비 상태만 표시하며 예제 방문·회원 데이터는 넣지 않는다.
- 구현이 요청된 목록은 페이지의 미리보기 데이터를 전달해 API 없이 확인할 수 있게 한다.

## 6. 상호작용
- 메뉴는 구즉과 같은 공통 버튼과 라우터 이동을 사용하고 로고는 목록 링크다. 뒤로·앞으로 이동과 새로고침을 지원한다.
- 드롭다운과 달력은 구즉의 `slideDown`과 동일하게 위쪽 10px·투명 상태에서 200ms `ease-out`으로 펼쳐진다. 닫힐 때는 구즉처럼 즉시 제거한다.
- 선택 버튼의 배경과 원형 표시 상태는 구즉과 같은 200ms 전환을 사용한다. `prefers-reduced-motion: reduce`에서는 드롭다운·달력 애니메이션과 선택 표시 전환을 끄며, 공통 버튼의 기존 효과도 줄인다.
- 방명록 삭제는 공통 `Modal`과 `useModal`로 확인·취소한다. 실제 삭제 전에는 API 미연결 안내를 제공한다.

## 7. 표면과 자산
- 흰 사이드바와 법동 기본색 배경을 유지한다.
- 내보내기 테두리·그림자는 공통 버튼을 유지한다.
- 로고와 내보내기 아이콘은 Figma에서 받은 로컬 원본만 사용한다.
- 안내 영역의 모서리는 공통 `components.fieldRadius`를 따른다.

## 8. 접근성과 확인 범위
- 메뉴는 키보드로 이동할 수 있고 현재 메뉴에 `aria-current="page"`를 제공한다.
- 본문 건너뛰기 링크와 제목 포커스 대상을 제공한다.
- 로고 대체 텍스트는 기관명이며 내보내기 아이콘은 장식 이미지다.
- 데스크톱·태블릿·390px 화면에서 이동·활성 상태·잘림·스크롤을 확인한다.
- 신규 기능 두 화면의 경로는 법동 앱 내부에만 두며 본문 기능은 확정 후 구현한다.

## 9. 코드 작성 기준
- 구즉 관리자와 대응하는 파일명·폴더 구조·컴포넌트 작성 방식을 우선 따른다.
- Router는 페이지별 Route를 명시하고 lazy/Suspense로 불러온다. 메뉴 설정으로 라우트를 생성하지 않는다.
- 페이지와 App은 default export, 위젯·공통 컴포넌트는 기존 public index 패턴을 따른다.
- 왼쪽 사이드바는 `widgets/admin-header`의 `AdminHeader`로 구성한다.
- 로직과 JSX는 상단, styled 선언은 하단에 작성한다.

## 10. 방명록 목록·상세
- 목록은 제공된 카드 이미지의 순서인 이름 → 이용대장(` / ` 구분) → 별도 인원 → 날짜 → 빨간 삭제 아이콘을 따른다.
- 기본 카드 크기·모서리·글꼴은 공통 `RecordCardParts`를 재사용한다. 이름은 공통 2rem·600, 요약은 1.5rem, 날짜는 1.25rem이다.
- 법동 요약은 `colors.secondaryText`, 삭제는 `colors.error`로 표시한다. 이용대장과 긴 이름은 잘라 숨기지 않고 줄바꿈한다.
- 긴 이름은 균형 있게 줄바꿈하며, 모달 제목은 한국어 어절을 유지한다. 법동 삭제 확인 버튼은 대비를 위해 `colors.error` 배경에 흰 글자를 사용한다.
- 목록 간격은 1.5rem이며, 카드 본문 상세 링크와 삭제 버튼은 서로 독립적인 키보드 대상을 가진다.
- 목록 제목과 카드는 동일한 최대 80rem 너비에서 가운데 정렬하며 화면이 줄어들면 양쪽 여백이 함께 줄어든다.
- 상세는 구즉과 같은 본문 최대 60rem·패딩 2.5rem·상하 여백 3.75rem을 따른다. 법동의 border-box 기준 외곽 최대 너비는 패딩을 포함한 65rem이며 좁은 화면에서는 본문 너비 안으로 제한한다. 내부 50rem 제한을 추가하지 않는다.
- 상세 목록 복귀 링크는 밑줄 없이 표시한다. 본문 위의 별도 제목은 시각적으로 숨기고 접근성 제목으로 유지한다.
- 이름·연령은 두 열, 성별·연락처·이용대장·방문 날짜·방문 시간은 각각 한 행이다. 좁은 화면에서는 한 열로 전환한다.
- 상세 필드는 공통 3.5rem 높이·0.5rem 모서리·1.25rem 텍스트를 유지한다. 긴 값은 높이를 늘려 표시한다. 조회 상태에는 드롭다운 화살표가 없으며 왼쪽 필드 아이콘은 유지한다.
- 편집 시 성별·이용대장은 공통 `SelectOption`을 사용한다. 구즉 `ToggleSelect`처럼 옵션은 2열·0.5rem 간격의 개별 테두리 버튼으로 펼쳐지고 원형 선택 표시를 사용한다. 성별은 단일 선택, 이용대장은 복수 선택이며 선택 표시는 `colors.primary`, 배경은 `colors.selected`를 사용한다.
- 방문 날짜 편집은 구즉과 같은 `react-calendar` 기반 공통 `VisitDatePicker`를 사용한다. 달력의 탐색 행·요일·날짜 간격과 0.75rem 패널 모서리·1.25rem 패딩은 구즉을 따르며 활성 날짜는 `colors.primary`, hover·오늘 표시는 `colors.primaryLight`다. 날짜 패널은 화면 너비 안에서 표시한다.
- 연령은 숫자 직접 입력과 왼쪽 아이콘을 유지하고 증가·감소 스피너만 숨긴다. 방문 시간은 시계 아이콘과 텍스트 입력을 사용하며 `visitTime: "17:00"`처럼 24시간 `HH:mm` 문자열로 조회·편집한다.
- 상세의 공통 버튼은 수정 → 편집 필드·저장·취소로 전환한다. 이용대장은 여러 항목을 유지하며 방문 날짜는 날짜 입력으로 수정한다. 저장 시 API 미연결 안내를 제공하고 원본 미리보기 데이터는 변경하지 않는다.
- API 연결 전에는 사용자 요청에 따라 미리보기 데이터를 표시한다.
- 목록과 상세는 데이터 props를 받는 표시 컴포넌트로 분리한다. 페이지에서 API 응답을 연결하는 작업은 후속이다.
- 삭제 확인 모달은 기본 공통 스타일과 상태 로직을 재사용한다. 취소·배경 닫기·확인 후 안내를 확인한다.
- 공통 모달은 dialog 이름·설명, 첫 버튼 포커스, Tab 순환, Escape 닫기, 닫은 후 포커스 복귀를 제공한다. 32rem 이하에서는 여백을 포함한 너비로 화면 안에 배치한다.
- 모달 열림 여부는 설정 유무와 함께 갱신한다. 지연된 닫기 타이머가 새 모달을 지우지 않으며, 안내로 전환할 때도 포커스를 모달 안에 유지한다.
- 회귀 검증용 데이터와 테스트 화면은 임시로 사용하고 검증 후 삭제한다.
- 방명록 미리보기 데이터는 `pages/log/model/previewVisits.ts`에서 목록과 상세가 함께 사용한다. 카드 ID에 해당하는 상세를 표시하며 실제 삭제는 수행하지 않는다. API 연동 시 페이지의 미리보기 데이터 연결을 대체한다.

## 11. 방명록 추가
- `/log/create`는 구즉과 같은 `pages/log/UserDetail` → `widgets/log/VisitForm` 구성으로 연결한다.
- 추가와 상세 페이지는 같은 페이지 패널을 사용하며, 상세 편집과 추가는 같은 `VisitFormFields`를 사용한다. 기존 상세의 값·간격·조회/편집 전환·취소 동작을 먼저 기록한 후 필드와 패널만 분리하고 회귀를 비교한다.
- 이름·연령·성별·연락처·이용대장·방문 날짜·방문 시간 순서로 7개 필드를 배치한다. 빈 값으로 시작하며 이름·연령은 두 열, 좁은 화면에서는 한 열이다.
- 성별은 단일 선택, 이용대장은 복수 선택, 방문 날짜는 공통 달력을 사용한다. 아이콘·숫자 스피너 숨김·법동 색상·펼침 애니메이션은 상세 편집과 같다.
- 추가 버튼은 구즉처럼 필수 입력 누락 시 공통 모달로 안내한다. 연령은 0 이상의 정수로 입력하며 `16`과 `16세` 표기를 허용하고 숫자 키보드를 제공하는 텍스트 입력을 사용한다. 방문 시간은 `00:00`~`23:59`의 `HH:mm` 형식으로 입력하고 형식이 맞지 않으면 공통 모달로 안내한다. 이름·연락처의 공백만 입력한 값은 누락으로 처리한다.
- 이름·연락처 placeholder는 구즉 문구를 사용하고, 연령은 단위가 포함된 예시를, 방문 시간은 `17:00` 예시를 제공한다. 성별·이용대장·방문 날짜도 선택 안내 문구를 표시한다. 추가와 상세 편집은 같은 안내를 사용한다.
- 모든 필드를 입력해도 실제 API는 호출하지 않으며, 등록 API 미연결 안내를 표시하고 입력값을 유지한다. 등록 성공이나 목록 데이터 변경을 가장하지 않는다.
- 이용대장 선택지는 목록·상세와 같은 미리보기 데이터를 페이지에서 전달하고, 실제 목록 조회와 등록 API는 후속으로 연결한다.

## 12. 이용대장 관리
- 법동 보드의 열은 사이드바를 제외한 실제 본문 너비 안에서 줄어들도록 최소 너비를 0으로 재정의해 중간 화면에서 오른쪽 카드가 잘리지 않게 한다. 구즉 기본 열 규격은 유지한다.
- `/purpose/all`은 구즉의 `PurposeCustom` → `PurposeBoard` 구조와 타일·인라인 추가/수정·삭제 확인 모달을 따른다. 카드 기본 높이 9rem, 간격 1.5rem, 최대 너비 75rem, 3열/2열/1열 전환은 구즉 정렬 보드와 공유한다.
- 구즉 보드와 정렬 항목은 기존 기본값·스타일·경계 제한을 기록하고 공통 패키지로 옮긴다. 구즉은 기존 export 경로를 유지하며 동일한 기본 props의 출력이 유지되는지 소스 계약과 빌드로 확인한다.
- 첨부 캡처처럼 추가 타일을 첫 번째에 배치하고 순번은 표시하지 않는다. 컴퓨터·노래방·당구대/탁구는 자물쇠 아이콘으로 이름 수정·삭제를 잠그고 순서 이동은 허용한다. 보드게임은 수정·삭제할 수 있다.
- 일반 타일은 공통 `TileCardParts`를 사용한다. 흰 표면·1.25rem 모서리·1.5rem 글자와 그림자는 구즉을 유지하고 추가·선택·포커스 강조는 법동 테마를 따른다. 긴 이름은 줄바꿈한다.
- 추가 타일은 구즉과 공통 `AddTileParts`를 사용한다. 그림자 없이 닫힌 상태는 2px 점선, 열린 상태는 1px 실선이며 입력창(70%, 22px, 왼쪽 정렬)과 오른쪽 확인·취소 아이콘(26px, 간격 15px)을 한 줄로 배치한다. 좌우 패딩 16px과 `목적을 입력하세요` 문구를 공유하고 법동에서는 테두리·밑줄·확인·취소·호버 색상만 테마로 지정한다. 구즉의 기존 색상 기본값과 동작은 유지한다.
- 마우스 8px 이동·터치 250ms 길게 누르기·키보드 Space/화살표/Space 정렬을 구즉처럼 제공한다. 모바일은 세로 스크롤을 허용하고 이동은 보드 경계를 벗어나지 않는다. 동작 줄이기에서는 정렬 전환 효과를 끈다.
- 추가 타일은 이름 입력과 확인·취소 버튼으로 전환한다. Enter로 확인하고 Escape로 취소한다. 빈 값은 공통 입력 확인 모달로 안내한다. 이름 편집은 구즉처럼 Enter/blur로 확인하고 Escape로 취소하며 한글 조합 중 Enter는 제출하지 않는다.
- 실제 생성·수정·삭제는 API 연결 전 안내를 표시하고 원본 미리보기 목록을 변경하지 않는다. 정렬은 현재 화면의 미리보기 순서만 변경하고 새로고침하면 초기 순서로 돌아간다.
- 카드와 아이콘 버튼에 구분되는 접근성 이름과 키보드 포커스를 제공한다. 숨긴 페이지 제목을 건너뛰기 링크의 대상으로 유지하고 이동 결과를 live 영역으로 알린다.

## 13. 회원 목록
- `/organ/user/all`은 구즉의 회원 검색창과 카드 규격을 공유한다. 검색창은 캡처의 알약 형태 대신 기존 공통 `SearchBar`의 3.75rem 높이·1rem 모서리·왼쪽 검색 아이콘·오른쪽 초기화 버튼을 사용한다.
- 검색·결과 수·빈 결과·목록 간격은 공통 `UserListLayout`으로 구성한다. 구즉의 거주지 선택은 필터 슬롯으로 유지하며 법동에는 추가하지 않는다. 검색 상태와 한글 초성·공백·대소문자 처리는 공통 `useNameSearch`를 사용한다.
- 공통 `UserInformationCard`는 구즉의 80rem 최대 너비·10rem 최소 높이·1.25rem/2rem 패딩·공통 모서리와 글꼴을 유지한다. 법동은 학교·학년, 이름, 생년월일(YYYY.MM.DD), 연락처, 방문 횟수를 표시한다. 구즉의 거주지·성별·날짜 표시는 기존 값을 유지한다.
- 카드·검색 행은 최대 80rem에서 가운데 정렬한다. 구즉과 같은 64rem/40rem 반응형 전환을 사용하며 긴 값은 줄바꿈하고 문서가 세로 스크롤을 담당한다.
- 수정 버튼은 기존 `/organ/user/:userId` 경로로 이동한다. 회원 상세 구현과 API 연동은 후속이다. API 연결 전 데이터는 `pages/user/model/previewUsers.ts`에서 전달한다.
